シーンを組むためのエディタです。UI に依存しないコアの上に、UI を載せ替えられる構成にしていて、現在は UI を C# の自前フレームワークへ移している途中です（ADR 037）。

### エディタコア

UI に依存しない C++ の静的ライブラリです。シーンの編集、選択、Undo、アセットブラウザ、クックの実行、ビューポートのカメラとギズモ、プレイモードを持ちます。UI を作り直しても、ここはそのまま引き継ぎます。

ウィンドウなしで動く `NexusEditorHeadless` もあり、`--smoke` の検査を CI や自動化から回せます。

### C ABI

コアを WinUI 3 のシェルへ渡すための境界で、`NexusEditorHost.dll` として出しています（ADR 013）。ヘッダは C99 の型だけで書いています。エンジンは例外と RTTI を切ってビルドしますが、C++/WinRT はそれらを要求し、STL の中身が `_HAS_EXCEPTIONS` で変わるためです。混ぜると実行時に壊れます。

WinUI 3 のシェルは、新しい UI が同等の機能に達した時点で撤去します（ADR 037 の P4）。この ABI の DLL もそのとき不要になります。

### C# UI

WinUI 3 と XAML をやめ、UI を C# のコードだけで定義する自前のフレームワーク（`Nexus.UI`）と、その上のエディタ（`Nexus.Editor`）に作り替えています（ADR 037）。理由は、変更通知が粗いこと、ビューポートが子ウィンドウで UI と重ねられないこと、シェルの検証が CI に乗らないことでした。

UI は毎フレーム描画コマンドを作って、前のフレームとの差分だけをエンジンの RHI で描きます。入力と描画の裏側を差し替えられるので、ウィンドウなしで UI をテストでき、要素は座標でなく ID で指定できます。

ドッキング、コマンドとショートカット、パネル、仮想化リスト、テキスト編集のコードは入っています。ただし移行は途中で、置き換え先の実行ファイルは `NexusEditorNext` という仮の名前です。
