アプリケーションの起動からゲームの進行、開発用のコンソールまでをまとめたモジュールです。ウィンドウ、デバイス、スワップチェーンの用意もここで引き受けます。

### ゲームループ

`Application` が初期化とメインループを持ち、1 フレームの経過時間は 0.05 秒で打ち切ります。ウィンドウが最小化されて大きさが 0 になると描画を止めます。`--no-vsync` のように、全デモで共通の起動オプションもここで解釈します。

更新の順序づけには、別に `FrameScheduler` があります。更新を 4 つのグループ（PreUpdate、FixedUpdate、Update、LateUpdate）に分け、固定ステップの回数も数えられます。`Application` のループとは独立したクラスで、エンジンの他のモジュールからはまだ呼ばれていません。

### 画面とフロー

起動・メニュー・プレイ・ポーズといった大きな流れは、トリガーで遷移する状態機械（`GameFlow`）で表します。どの状態からでも遷移できる指定もできます。画面の積み重ねは `ScreenStack` で、積む・外す・置き換えるの 3 操作と、入退場のコールバックを持ちます。

### UI

ゲーム内 UI は、Dear ImGui を使います（ADR 012）。このモジュールにあるのは、Flexbox 風のレイアウト計算（`UiLayout`）と、イージング付きのトゥイーン（`UiAnim`）です。

C# で作ったエディタの UI フレームワーク（`Nexus.UI`）は、エディタに依存しない形を保っています。ゲーム内 UI に使うかどうかは、エディタの移行が終わってから決めることになっています（ADR 037）。

### シネマティクス

位置のカーブ、回転のキー、フェード、イベントを時間軸に並べるタイムラインがあります。再生・一時停止・終了の状態を持ちます。時刻ごとにイベントを発火させるだけの、より小さな `Sequencer` も別にあります。

FMV 用には、独自の動画コンテナ形式（NXV）とプレイヤーがあります。ただしデコーダはインターフェースだけで、実装はテスト以外にありません。

### コンソール

コマンドの登録と実行、CVar の確認と変更、ログの履歴、入力履歴、前方一致の補完を持つ、描画に依存しない層です。リモートコンソールは、動いているゲームが TCP サーバになり、外部のツールがコマンド実行や統計・プロファイルの取得をする仕組みです。メッセージは長さ付きの単純な枠で、telnet でも確認できます。

### ローカライズ

言語ごとの文字列表を、キー（StringId）から引きます。表示する言語と、足りないときのフォールバック言語を、別々に指定できます。
