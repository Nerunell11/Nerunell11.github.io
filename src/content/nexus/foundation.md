ほかのすべてのモジュールが載る土台です。メモリ、スレッド、数学、コンテナ、リフレクション、計測を担当します。例外と RTTI を使わないので、エラーは `Result<T>` で返し、確保はアロケータ経由に統一しています。

### メモリアロケータ

`IAllocator` を共通の入口にして、リニア、スタック、プール、TLSF の 4 種類を用意しています。`new` / `delete` を直接書かない代わりに、使う側が用途に合う確保方法を選べるようにするためです。

たとえばリニアは確保を進めるだけで `Free` が何もしないので、フレーム境界で `Reset` して使います。TLSF は単一スレッド前提の汎用ヒープで、同期が必要ならそれを持つモジュール側で入れます。確保量はカテゴリ別に集計して、予算を超えたものを検出するトラッカーもあります。

### ジョブシステム

ワーカーごとのキューを持ち、空いたワーカーが他のキューの先頭から仕事を取る（ワークスティーリング）方式です。待つ側も、待つ前にキューにある仕事を実行します。`ParallelFor` は粒度を指定して使います。

初期の実装は、投入したジョブの状態を一度も解放していませんでした。NexusDefense で毎秒 245 MB ずつメモリが増えて気づいたので、完了した状態を再利用し、ハンドルに世代番号を持たせる形に直しています（ADR 021）。

### 数学・コンテナ

数学は Vec2 / Vec3 / Vec4、Mat44、Quat に加えて、境界ボリューム、交差判定、カーブ、ノイズ、半精度浮動小数などです。コンテナは `Array`、`HashMap`、`SlotMap`、`ObjectPool`、`RingBuffer`、`BitSet` などを自作しています。

`ChunkedArray` は要素のアドレスが動かないことを保証するためのコンテナです。`Function` は小さなラムダを確保なしで持てるようにして、ジョブの投入で確保が起きにくいようにしています。

### リフレクション

`NX_REFLECT` でフィールドを登録し、型ごとの `TypeInfo` を引けるようにしています。RTTI を使わないので、型情報は登録したものだけです。

この情報を 3 か所が共有しています。シーンの JSON 保存、ネットワークのレプリケーション（フィールドの送信定義をここから作ります）、エディタのインスペクタです。

### プロファイラ

CPU 側はスレッドごとのバッファに区間を記録する方式で、計測の開始と終了は他のスレッドと同期しません。Chrome Tracing 形式の JSON に書き出せるので、専用の閲覧ツールは要りません。出荷ビルドではマクロごと消えます。

フレームごとの数値（システムの所要時間など）を流す別の仕組みがあり、直近のフレームの平均と最大を取れます。ECS のシステム別計測にプロファイラを使わなかったのは、サンプルのバッファがスレッドごとに際限なく伸びるためです（ADR 019）。

### 設定（CVar）

CVar は bool / i32 / f32 / 文字列の 4 種類で、名前・説明・フラグ（再起動が必要、読み取り専用）を持ちます。値は INI ファイルとコマンドライン引数から適用でき、デバッグコンソールからも確認・変更できます。
