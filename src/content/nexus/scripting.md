ゲームロジックを C++ 以外でも書けるようにするための層です。C++ のネイティブ DLL、C#、Python の 3 通りを想定しています（ADR 007）。言語のランタイムは外部のものを使い、エンジンに橋渡しするホスト層を自作します。

### .NET ホスト

nethost / hostfxr で CoreCLR を起動し、C# の `[UnmanagedCallersOnly]` な静的メソッドを、C の関数ポインタとして受け取ります。C# 側からは普通の C 関数のように呼べます。

起動まで来ていて、できるのは関数ポインタを引くところまでです。.NET の SDK が見つかったときだけ有効になり、無い環境ではホストは「使えない」と返すだけで、エンジンはそのままビルドできます。エディタの新しい C# の UI は、このホストを通して起動します（ADR 037）。

### Python ホスト

CPython を組み込み、文字列のコードの実行、式の評価（整数と浮動小数）、定義済みの関数を整数で呼ぶところまでを提供しています。ゲームのオブジェクトを触れるようにするバインディングは、まだありません。

Python の開発用ランタイムが見つかったときだけ有効になり、無い環境では何もせず「使えない」と返します。

### ネイティブモジュール

ゲームのコードを DLL にして読み込み、再読み込みできます。DLL は `NxGetGameModule` という入口だけを公開する C の ABI（バージョン番号つき）で、ABI が合わなければ読み込みを断ります。

現在のゲーム側の状態は、時刻・カウンタ・位置 64 個だけの小さな構造体です。エンジンの ECS を C++ のゲーム DLL から触る段階には、まだ来ていません。
